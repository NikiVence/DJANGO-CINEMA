# Как устроен проект и за что отвечает каждый файл

Начни с этой цепочки:

```text
Браузер запрашивает /sessions/?tickets=50
    ↓
cinema_sessions/urls.py выбирает приложение sessions
    ↓
sessions/urls.py выбирает функцию session_list
    ↓
sessions/views.py читает tickets, проверяет ввод
    ↓
sessions/db.py выполняет запрос из sql/queries.sql через sqlite3
    ↓
data/sessions.db возвращает записи
    ↓
views.py передаёт записи в context
    ↓
session_list.html перебирает записи и подключает session_card.html
    ↓
base.html добавляет общую оболочку, CSS и JavaScript
    ↓
Браузер получает готовый HTML
```

`context` — обычный Python-словарь. Например,
`{"sessions": [...]}` позволяет шаблону обращаться к переменной `sessions`.
Шаблон сам не ходит в базу: данные для него готовит view.

## Почему две папки cinema_sessions

Внешняя `cinema_sessions/` — папка всего Django-проекта: здесь `manage.py`,
приложения, база, шаблоны и статика.

Внутренняя `cinema_sessions/cinema_sessions/` — Python-пакет общих настроек
и маршрутов. Далее все пути, кроме раздела «Корень репозитория»,
указаны относительно внешней папки `cinema_sessions/`.

## Запуск и общие настройки

| Файл | Назначение |
| --- | --- |
| `manage.py` | Точка входа для команд: `runserver` запускает сервер, `check` проверяет настройки, `test` запускает тесты, `init_db` создаёт учебную базу. |
| `cinema_sessions/__init__.py` | Обозначает Python-пакет. Пустой: отдельная логика здесь не нужна. |
| `cinema_sessions/settings.py` | Общая конфигурация: приложения, расположение шаблонов и статики, путь к базе, язык, часовой пояс, режим отладки. `DATABASES = {}`, потому что данные читаются через `sqlite3`, без ORM. |
| `cinema_sessions/urls.py` | Главный диспетчер адресов. `/` передаётся в `homepage`, `/halls/` — в `halls`, `/sessions/` — в `sessions`. Здесь же указан обработчик 404. |
| `cinema_sessions/wsgi.py` | Предоставляет объект приложения для WSGI-сервера; используется стандартным сервером разработки Django. |
| `cinema_sessions/asgi.py` | Предоставляет объект приложения для ASGI-сервера. Это альтернативный интерфейс запуска, в обычной демонстрации менять его не нужно. |

## Приложение homepage — главная

| Файл | Назначение |
| --- | --- |
| `homepage/urls.py` | Связывает адрес `/` с функцией `home`. Имя маршрута — `homepage:home`. |
| `homepage/views.py` | Функция `home` получает общее число сеансов и первые три сеанса по дате через `db.py`, затем передаёт их шаблону. |
| `homepage/templates/homepage/home.html` | Главная страница: название, описание, кнопки перехода, общее число сеансов и три карточки. |
| `homepage/tests.py` | Проверяет главную, навигацию, наличие статики и использование общего шаблона всеми основными страницами. |

## Приложение halls — залы

| Файл | Назначение |
| --- | --- |
| `halls/urls.py` | Связывает `/halls/` с функцией `hall_list`. Имя маршрута — `halls:list`. |
| `halls/views.py` | Получает список залов из базы и передаёт его шаблону как `halls`. |
| `halls/templates/halls/hall_list.html` | Перебирает залы, показывает название, вместимость и тип. Если залов нет, выводит сообщение. |
| `halls/tests.py` | Проверяет, что изменение названия и вместимости зала в SQLite видно на страницах залов и связанного сеанса. |

## Приложение sessions — сеансы и статистика

| Файл | Назначение |
| --- | --- |
| `sessions/urls.py` | Маршруты списка, статистики и подробностей. Статистика объявлена перед `<slug:slug>`, чтобы слово `statistics` не воспринималось как slug фильма. |
| `sessions/views.py` | Обрабатывает запросы: читает GET-параметры, проверяет их, вызывает слой базы, формирует контекст и возвращает HTML с нужным HTTP-статусом. |
| `sessions/db.py` | Единственный слой чтения данных: подключается к SQLite, выполняет именованные SQL-запросы с параметрами, преобразует строки в словари, даты — в `datetime`, закрывает соединение. |
| `sessions/tests.py` | Проверяет фильтрацию, сортировку, LIMIT, SQL, статусы, подробности, 404, ошибки базы, статистику и изменения данных. Здесь же общая тестовая база `CinemaTestCase`, которую используют остальные тесты. |
| `sessions/templates/sessions/session_list.html` | Форма GET-фильтрации, число показанных записей и цикл по сеансам. Для каждого подключает шаблон карточки. |
| `sessions/templates/sessions/session_detail.html` | Полная информация об одном сеансе и зале, кнопка раскрытия советов перед посещением. |
| `sessions/templates/sessions/statistics.html` | Форма минимального количества сеансов в группе и таблица статистики по типам. |
| `sessions/templates/sessions/includes/session_card.html` | Одна карточка сеанса. Используется в списке и на главной, чтобы не дублировать HTML. |
| `sessions/templates/sessions/includes/status.html` | Через `if/elif` показывает разный текст и оформление для запланированного, идущего и завершённого показа. |
| `sessions/management/__init__.py` | Обозначает пакет пользовательских команд Django. |
| `sessions/management/commands/__init__.py` | Обозначает пакет, в котором Django ищет реализации команд. |
| `sessions/management/commands/init_db.py` | Реализация `python manage.py init_db`: выполняет `schema.sql` и `seed.sql`, создавая таблицы и добавляя недостающие демонстрационные записи. |

### Функции views.py

| Функция | Что делает |
| --- | --- |
| `database_page` | Декоратор: оборачивает view, ловит `sqlite3.Error`, записывает причину в журнал и возвращает страницу ошибки базы с HTTP 503. Применяется также к главной и залам. |
| `integer_parameter` | Читает число из `request.GET`, проверяет диапазон. При неверном вводе добавляет сообщение в список ошибок. |
| `session_list` | Читает `tickets`, `sort`, `limit`, получает отфильтрованные записи и отображает список. При ошибочных параметрах возвращает HTTP 400. |
| `session_detail` | Получает сеанс по slug. Если его нет — выбрасывает `Http404`, иначе показывает подробности. |
| `statistics` | Читает `minimum`, получает группы сеансов и общее число записей. |
| `not_found` | Отрисовывает собственный шаблон 404. |

### Функции db.py

| Функция или переменная | Что делает |
| --- | --- |
| `SORT_OPTIONS` | Допустимые варианты сортировки и их подписи в форме. |
| `load_queries` | Читает `queries.sql` и разделяет запросы по комментариям `-- name: ...`. |
| `QUERIES` | Словарь SQL-запросов. Загружается при импорте модуля; сами записи базы заново читаются на каждом запросе страницы. |
| `fetch` | Выполняет выбранный запрос с параметрами. `mode=ro` открывает базу только для чтения и не создаёт пустой файл при ошибке пути. |
| `get_sessions` | Список сеансов: фильтр по билетам, сортировка и ограничение количества. |
| `get_session` | Один сеанс со сведениями о зале или `None`, если slug не найден. |
| `get_halls` | Список залов. |
| `get_count` | Общее число сеансов через `COUNT(*)`. |
| `get_statistics` | Группировка сеансов по типам с порогом `HAVING`. |

| Файл | Назначение |

## База и SQL

| Файл | Назначение |
| --- | --- |
| `data/sessions.db` | Настоящий бинарный файл SQLite с таблицами `halls` и `sessions`. Здесь хранятся текущие записи. Открывается через SQLite-клиент или Python `sqlite3`, а не как текст. |
| `sql/schema.sql` | Структура: таблицы, столбцы, внешняя связь `hall_id`, ограничения и индексы. |
| `sql/seed.sql` | Начальные данные: 4 зала и 8 сеансов. `INSERT OR IGNORE` позволяет повторно запускать инициализацию, сохраняя уже существующие записи. |
| `sql/queries.sql` | Запросы, которые реально использует сайт: список с JOIN, WHERE, ORDER BY, LIMIT; подробности; залы; COUNT; GROUP BY и HAVING. |

Фильтр `tickets=50` означает **не менее 50 проданных билетов**.
SQL сравнивает `s.tickets >= :tickets`, а значение `50` передаётся отдельно.
Пользовательский текст не склеивается с SQL.

`WHERE` отбирает отдельные записи до группировки.
`HAVING` отбирает уже сформированные группы: например, типы, у которых
`COUNT(*) >= 3`.

## Общие шаблоны

| Файл | Назначение |
| --- | --- |
| `templates/base.html` | Общая HTML-оболочка: заголовок вкладки, логотип, навигация, CSS, JS, сообщения об ошибках, подвал и блок `content`. Остальные страницы расширяют её через `extends`. |
| `templates/404.html` | Понятная страница для неизвестного адреса или отсутствующего сеанса. |
| `templates/database_error.html` | Сообщение о временной недоступности данных без технических подробностей, HTTP 503. |

Основные конструкции шаблонов:

| Конструкция | Для чего используется |
| --- | --- |
| `{% extends 'base.html' %}` | Берёт общую оболочку страницы. |
| `{% block content %}` | Определяет содержимое конкретной страницы внутри оболочки. |
| `{% include ... %}` | Вставляет повторно используемый фрагмент: карточку или статус. |
| `{% for ... %}` / `{% empty %}` | Перебирает записи или показывает сообщение, если список пуст. |
| `{% if ... %}` | Выбирает отображение в зависимости от данных. |
| `{% url 'sessions:detail' session.slug %}` | Строит ссылку по имени маршрута и slug записи. |
| `{% load static %}` / `{% static ... %}` | Подключает статические файлы. |
| `{{ session.show_date\|date:"d.m.Y" }}` | Форматирует дату. |
| `default`, `length`, `upper`, `truncatechars`, `capfirst` | Подставляет запасной текст, считает элементы, меняет регистр или сокращает длинный заголовок. |

## Статика

| Файл | Назначение |
| --- | --- |
| `static/css/style.css` | Внешний вид: цвета, размеры, сетки карточек, формы, таблицы, состояния, адаптация под телефон. |
| `static/js/main.js` | Обработчик кнопки советов: показывает/скрывает блок и меняет `aria-expanded`. Без JS текст остаётся доступным, кнопка скрыта. |
| `static/img/logo.png` | Изображение логотипа в шапке сайта. |
| `static/img/logo.svg` | Векторная версия логотипа, используется как значок вкладки браузера. |
| `static/img/make_logo.py` | Вспомогательный скрипт для повторного создания `logo.png`. При запросах страниц не запускается. |

Папки `__pycache__/` и файлы `.pyc` создаёт сам Python для ускорения загрузки.
Это не исходный код проекта, их не нужно изучать или добавлять в Git.

## Что открыть, если нужно что-то изменить

| Задача | Файлы |
| --- | --- |
| Изменить оформление | `static/css/style.css` |
| Изменить меню всех страниц | `templates/base.html` |
| Изменить карточку фильма | `sessions/templates/sessions/includes/session_card.html` |
| Добавить фильтр | `sessions/views.py`, `sessions/db.py`, `sql/queries.sql`, `session_list.html` |
| Изменить данные фильма | Запись в `data/sessions.db`; `seed.sql` — для начального наполнения новых баз |
| Изменить правила статистики | `sql/queries.sql`, при необходимости `sessions/views.py` и `statistics.html` |
| Добавить страницу | Маршрут в `urls.py`, функция в `views.py`, HTML-шаблон |

## Как объяснить проект на защите

«В проекте три приложения: главная, залы и сеансы. URL-диспетчер выбирает
view-функцию. Она проверяет параметры запроса и вызывает слой доступа к базе.
Этот слой выполняет параметризованный SQL через sqlite3 и возвращает словари.
View передаёт их в context, а Django-шаблоны формируют HTML. Оформление общее
через base.html и CSS. ORM не используется. Фильтрация, сортировка, ограничение
и статистика выполняются в SQL. Несуществующий сеанс даёт 404, ошибка базы —
503, неправильные параметры — 400».
