# КАДР — Кинопоказы

Реализация задания из `readme.md`. Проект расположен в `cinema_sessions/`.
Требуется Python 3.10+ и Django 5.2. Все данные читаются через стандартный
`sqlite3`; Django ORM, миграции и административная панель не используются.

## Запуск в Windows PowerShell

Откройте терминал PowerShell в IDE. Окружение `.venv` уже создано,
Python находится в `.venv\Scripts\python.exe`. Активировать окружение не нужно.

После пересоздания окружения один раз установите зависимости:

```powershell
cd D:\PythonDev\kr_2
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для запуска сайта:

```powershell
cd D:\PythonDev\kr_2
.\.venv\Scripts\python.exe cinema_sessions\manage.py runserver --insecure
```

Оставьте терминал открытым и перейдите в браузере на http://127.0.0.1:8000/.
Чтобы остановить сервер, нажмите Ctrl+C в терминале.

Если появилось `No module named django`, выполните команду установки
зависимостей выше. Если порт 8000 занят, запустите на другом порту:

```powershell
.\.venv\Scripts\python.exe cinema_sessions\manage.py runserver 8001 --insecure
```

В этом случае адрес сайта — http://127.0.0.1:8001/.

`DEBUG=False` задан по умолчанию, чтобы показывать пользовательскую страницу
404, а не отладочную. Флаг `--insecure` позволяет локальному серверу Django
обслуживать CSS, JS и логотип при таком режиме. Это команда для локальной
демонстрации.

Готовая база `cinema_sessions/data/sessions.db` содержит 4 зала и 8 сеансов.
Команда `init_db` создаёт базу при отсутствии и добавляет недостающие демонстрационные
записи, сохраняя изменения существующих. На обычных веб-запросах база не
создаётся и не заполняется заново. Даты и статусы — фиксированные учебные данные;
статусы не пересчитываются по текущему времени.

Если файл базы отсутствует, создайте его перед запуском:

```powershell
.\.venv\Scripts\python.exe cinema_sessions\manage.py init_db
```

## Проверки

Выполняйте из `D:\PythonDev\kr_2`. Команда `check` проверяет конфигурацию,
но не запускает сайт; для запуска используется `runserver` выше.

```powershell
.\.venv\Scripts\python.exe cinema_sessions\manage.py check
.\.venv\Scripts\python.exe cinema_sessions\manage.py test homepage halls sessions
```

Тесты работают с отдельной временной базой и не меняют демонстрационные данные.

## Сценарий демонстрации

1. `/` — описание, актуальное общее число сеансов, навигация.
2. `/halls/` — 4 зала с вместимостью и типом.
3. `/sessions/` — 8 сеансов; карточки подключаются через `{% include %}`.
4. `/sessions/?tickets=50` — 5 сеансов; `?tickets=100` — 3.
5. `/sessions/?tickets=9999` — сообщение об отсутствии результатов.
6. `/sessions/?sort=-tickets&limit=2` — два самых популярных показа:
   «Властелин колец» и «Интерстеллар».
7. `/sessions/matrix-classic/` — сеанс и связанный зал. Кнопка «Советы перед
   посещением» раскрывает и скрывает текст через JavaScript.
8. `/sessions/no-such-movie/` — собственная страница 404.
9. `/sessions/?tickets=abc` — понятная ошибка параметра, HTTP 400.
10. `/sessions/statistics/?minimum=3` — только вечерние показы (4).
    При `minimum=2` отображаются все три типа.

Для проверки ошибки БД временно переименуйте `data/sessions.db`, обновите
любую страницу, затем восстановите имя. Приложение вернёт HTTP 503 и понятное
сообщение без технических подробностей. Причина записывается только в консоль.

## SQL → Python → веб-страница

`sql/queries.sql` содержит именованные запросы. `sessions/db.py` загружает
их и выполняет через `sqlite3`. View-функции получают словари и передают их
шаблонам. Даты преобразуются в `datetime` для фильтра `date`.

Значения фильтра, лимита, порога `HAVING` и slug передаются параметрами.
Сортировка проверяется по допустимому списку и выполняется SQL-выражением
`ORDER BY CASE`; пользовательский ввод не вставляется в SQL.
Все соединения закрываются через `contextlib.closing`.

Имена запросов и страницы:

| Запрос | Где используется |
| --- | --- |
| `session_list` | Главная, список, фильтрация, сортировка, LIMIT |
| `session_detail` | Подробности сеанса и зала через JOIN |
| `halls` | Список залов |
| `count` | Главная, статистика |
| `statistics` | COUNT, SUM, GROUP BY, HAVING на странице статистики |

Запросы можно выполнить в SQLite-клиенте, подставив параметры `tickets=50`,
`sort='date'`, `limit=-1`, `slug='matrix-classic'`, `minimum=3` там, где они нужны.
`limit=-1` — внутреннее значение «без ограничения» при пустом поле формы.

Для демонстрации обновления данных откройте базу в SQLite-клиенте и выполните:

```sql
PRAGMA foreign_keys = ON;
UPDATE halls SET name = 'Зал 1 · Обновлённый' WHERE id = 1;
UPDATE sessions SET tickets = 115 WHERE slug = 'matrix-classic';
```

Сохраните транзакцию и обновите страницы залов и «Матрицы»:
новые значения отобразятся без перезапуска сервера и правки шаблонов.

Чтобы проверить изменение групп HAVING, добавьте два показа:

```sql
INSERT INTO sessions
    (title, slug, show_type, show_date, duration, tickets, status, hall_id)
VALUES
    ('Утренний повтор', 'morning-extra-1', 'утренний',
     '2026-10-23 10:00:00', 90, 20, 'запланирован', 1),
    ('Ещё один утренний показ', 'morning-extra-2', 'утренний',
     '2026-10-24 10:00:00', 100, 30, 'запланирован', 2);
```

На главной будет 10 сеансов; при `minimum=3` статистика покажет
и вечерние, и утренние сеансы. Для возврата к исходным данным:

```sql
DELETE FROM sessions WHERE slug IN ('morning-extra-1', 'morning-extra-2');
UPDATE halls SET name = 'Зал 1 · Классика' WHERE id = 1;
UPDATE sessions SET tickets = 110 WHERE slug = 'matrix-classic';
```
