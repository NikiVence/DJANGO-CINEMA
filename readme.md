## 1. Задание

Разработать работающее Django-приложение для просмотра и фильтрации киносеансов.

Приложение должно использовать **SQLite, SQL, Python `sqlite3`, маршрутизацию Django, URL-конвертеры, view-функции, шаблоны Django, GET-параметры, фильтры шаблонов и статические файлы**.

Результатом должна быть работающая система, в которой данные проходят следующую цепочку:

**SQLite → SQL → Python `sqlite3` → Django view → context → Django templates → HTML/CSS/JavaScript.**

Приложение должно содержать:

* главную страницу;
* страницу залов;
* страницу списка сеансов;
* страницу конкретного сеанса;
* GET-фильтрацию сеансов;
* сортировку и ограничение выборки;
* статистические запросы;
* отображение результатов SQL-запросов на веб-страницах;
* обработку основных ошибок.

Django ORM для работы с данными в рамках контрольной работы не используется.

## 2. Предметная область и структура данных

Приложение работает с двумя связанными сущностями: «Зал» и «Сеанс».

### 2.1. Сущность «Зал»

| Поле        | Назначение                                |
| ----------- | ----------------------------------------- |
| `id`        | Уникальный идентификатор зала             |
| `name`      | Название или номер зала, например «Зал 3» |
| `capacity`  | Количество зрительских мест               |
| `hall_type` | Тип зала: стандартный, комфорт, VIP       |

### 2.2. Сущность «Сеанс»

| Поле        | Назначение                                            |
| ----------- | ----------------------------------------------------- |
| `id`        | Уникальный идентификатор сеанса                       |
| `title`     | Название фильма                                       |
| `slug`      | Уникальная текстовая часть URL для обращения к сеансу |
| `show_type` | Тип сеанса: утренний, дневной, вечерний               |
| `show_date` | Дата и время показа                                   |
| `duration`  | Продолжительность сеанса в минутах                    |
| `tickets`   | Количество проданных билетов                          |
| `status`    | Состояние сеанса: запланирован, идёт, завершён        |
| `hall_id`   | Идентификатор зала, в котором проходит показ          |

Поле `hall_id` должно связывать сеанс с соответствующим залом.

Создать не менее **4 залов и 8 сеансов**.

Данные должны содержать различные типы сеансов, даты, количества билетов, статусы и залы, чтобы результаты выборок, сортировки и фильтрации отличались друг от друга.

Из перечисленных фильтров необходимо использовать не менее трёх.

## 20. Принцип оценивания

**Практический результат без подтверждения соответствующей реализацией в коде не засчитывается.**

**Наличие требуемой конструкции в коде без её фактического использования в работающем сценарии также не засчитывается.**

Например:

* наличие `slug` без использования URL-конвертера не подтверждает выполнение критерия 15;
* наличие `{% extends %}` без использования общего шаблона для нескольких страниц не подтверждает выполнение критерия 20;
* вывод фиксированного количества сеансов вместо получения количества из базы данных не подтверждает выполнение критерия 4;
* GET-параметр, который изменяет результат только средствами Python без использования параметризованного SQL-запроса, не подтверждает выполнение критерия 12;
* SQL-запросы в `queries.sql`, которые не используются работающим приложением, не подтверждают выполнение соответствующих критериев;
* получение результата запроса в Python без передачи его в шаблон и отображения на веб-странице не подтверждает выполнение требования об отображении результатов в Web;
* отображение заранее заданных в HTML данных вместо результатов SQLite не подтверждает выполнение критериев получения и отображения актуальных данных;
* наличие подключённого CSS-файла без фактического изменения оформления страницы не подтверждает выполнение критерия 25;
* наличие файла JavaScript без его подключения и использования в интерфейсе не подтверждает выполнение критерия 26.

## 21. Порядок демонстрации

Работу демонстрировать в следующей последовательности:

**Запуск приложения → главная страница → навигация → страница залов → список сеансов → связанные данные → GET-фильтрация → отсутствие результатов → сортировка и ограничение → страница сеанса по `slug` → 404 → обработка ошибки БД → общий шаблон → карточка сеанса → условное отображение → фильтры шаблонов → статистические SQL-запросы → отображение статистики в Web → изменение данных → CSS и логотип → интерактивный элемент JavaScript → полный пользовательский сценарий.**

При демонстрации работы с базой данных студент должен:

1. Выполнить SQL-запрос в SQLite и показать полученный результат.
2. Открыть соответствующую страницу Django-приложения.
3. Продемонстрировать, что на странице отображаются данные из результата запроса.
4. Изменить запись в таблице `halls` или `sessions`.
5. Обновить страницу и показать актуальные данные.
6. Добавить несколько сеансов и проверить изменение статистики, включая результат запроса с `HAVING`.

Изменение данных выполняется непосредственно в SQLite. После изменения необходимо повторно обратиться к странице приложения и проверить, что она отображает актуальные данные базы.
